# AnythingAtlas

> **Map the best way into any topic.**
>
> **绘制进入任何主题的最佳路径。**

**AnythingAtlas** is an agent skill that helps users enter unfamiliar topics through reliable, structured, and personalized resource discovery.

**AnythingAtlas** 是一项智能体技能，通过可靠、结构化且个性化的资源发现，帮助用户进入陌生领域。

Instead of generating another generic reading list, AnythingAtlas first clarifies what the user actually needs, identifies the nature of the topic, builds a knowledge map, designs a source and channel plan, verifies the best materials, and turns them into a detailed roadmap delivered as both Markdown and polished HTML.

AnythingAtlas 不会再生成一份泛泛的阅读清单，而是先澄清用户的真实需求，再识别课题性质、构建知识图谱、设计来源与渠道方案、验证最佳材料，并将其转化为详细路线图，同时以 Markdown 和精美 HTML 两种形式交付。

```text
Initial user request
   ↓
Proactive clarification and confirmed brief
   ↓
Topic classification and analysis
   ↓
Knowledge map
   ↓
Source and channel plan
   ↓
Cross-channel discovery
   ↓
Verification and ranking
   ↓
Trusted resource atlas
   ↓
Detailed personalized roadmap
   ↓
Markdown file + polished HTML file
```

```text
用户的初步请求
   ↓
主动澄清并确认需求简报
   ↓
主题分类与分析
   ↓
知识图谱
   ↓
来源与渠道方案
   ↓
跨渠道发现
   ↓
验证与排序
   ↓
可信资源图谱
   ↓
详细的个性化路线图
   ↓
Markdown 文件 + 精美 HTML 文件
```

## Why AnythingAtlas?

**为什么选择 AnythingAtlas？**

When people begin exploring a new topic, the main problem is rarely a lack of information.

当人们开始探索一个新主题时，主要问题往往并不是缺少信息。

The real problems are:

真正的问题在于：

* not knowing where to start;

  不知道从哪里开始；

* not understanding the structure of the topic;

  不了解该主题的结构；

* not knowing which sources are trustworthy;

  不知道哪些来源值得信赖；

* not knowing which material types and information channels are appropriate for the topic;

  不知道哪些资料类型与信息渠道适合该课题；

* receiving too many undifferentiated recommendations;

  收到太多未经区分的推荐；

* not knowing which resource is suitable for their current level;

  不知道哪些资源适合自己当前的水平；

* not knowing what to read, watch, or build next;

  不知道接下来该读什么、看什么或动手做什么；

* receiving recommendations without a detailed roadmap for turning them into progress.

  收到推荐，却没有一份能将这些资源转化为实际进展的详细路线图。

General-purpose AI assistants can quickly generate lists of books, courses, and creators. However, these recommendations are often unverified, poorly prioritized, or disconnected from the learner’s actual goal.

通用 AI 助手可以快速生成书籍、课程和创作者清单。然而，这些推荐往往未经验证、优先级混乱，或者与学习者的实际目标脱节。

AnythingAtlas is designed to answer a more useful question:

AnythingAtlas 旨在回答一个更有用的问题：

> **What are the most trustworthy and appropriate ways for this user to enter this topic?**
>
> **对于这位用户而言，进入这个主题最可信、最合适的方式是什么？**

## What AnythingAtlas Does

**AnythingAtlas 能做什么**

AnythingAtlas begins with the user’s topic and actively clarifies the goal,
current background, urgency, available time, normal session length, language
preferences, preferred resource formats, desired depth, and access
constraints.

AnythingAtlas 从用户提出的主题出发，主动澄清目标、当前背景、紧迫程度、
可用时间、单次学习时长、语言偏好、偏好的资源形式、期望深度以及访问限制。

When the request is underspecified, AnythingAtlas asks focused follow-up questions before researching or generating the final atlas. It may infer low-impact preferences, but it should state those assumptions and seek confirmation whenever they could materially change the recommendations or roadmap.

当请求信息不足时，AnythingAtlas 会先提出聚焦的后续问题，再开展研究或生成最终图谱。对于影响较小的偏好，它可以作出推断；但只要某项假设可能实质性改变推荐或学习路线，就应明确说明该假设并向用户确认。

It then produces a structured knowledge atlas containing:

随后，它会生成一份结构化的知识图谱，其中包括：

* a confirmed brief of the user’s needs and constraints;

  一份经过确认的用户需求与限制条件简报；

* a direct, decision-useful orientation;

  直接且有助于决策的结论；

* a concrete field guide and practical action kit;

  具体的领域实战地图与实操工具箱；

* a map of its major concepts and branches;

  主要概念与分支的图谱；

* necessary prerequisite knowledge;

  必要的前置知识；

* a topic-specific plan for required materials and information channels;

  一份针对该课题所需资料与信息渠道制定的专属方案；

* resource tracks matched to the user's cadence and preferred formats;

  匹配用户节奏与内容形式偏好的资源路线；

* selected books and textbooks;

  精选书籍与教材；

* online courses and university lectures;

  在线课程与大学讲座；

* papers and academic surveys;

  论文与学术综述；

* blogs, newsletters, and technical articles;

  博客、简报与技术文章；

* researchers, educators, creators, and institutions;

  研究者、教育者、创作者与机构；

* videos, podcasts, documentaries, or archives;

  视频、播客、纪录片或档案；

* open-source projects, datasets, and practical exercises;

  开源项目、数据集与实践练习；

* a recommended order for using these resources;

  使用这些资源的推荐顺序；

* limitations, biases, and caveats for important sources;

  重要来源的局限、偏见与注意事项；

* a detailed, personalized learning or exploration roadmap with stages, milestones, exercises, time estimates, and completion criteria;

  一份详细且个性化的学习或探索路线图，包含阶段、里程碑、练习、时间估算与完成标准；

* two synchronized deliverables: a Markdown file and a polished HTML file.

  两份内容同步的交付文件：一份 Markdown 文件和一份精美的 HTML 文件。

The goal is not to collect the largest number of links.

目标并不是收集数量最多的链接。

The goal is to identify the **smallest high-quality set of resources that gives the user a reliable entry point**.

目标是找出一组**规模最小但质量足够高、能为用户提供可靠入口的资源**。

## Topic-Aware Resource Policy

**主题感知型资源策略**

A core principle of AnythingAtlas is:

AnythingAtlas 的一项核心原则是：

> **Different topics require different sources and different standards of credibility.**
>
> **不同的主题需要不同的来源，也需要采用不同的可信度标准。**

AnythingAtlas first classifies the topic before selecting its search and evaluation policy.

AnythingAtlas 会先对主题进行分类，然后再选择相应的搜索与评估策略。

| Topic type<br>主题类型 | Required or preferred materials<br>必需或首选资料 | Information and discovery channels<br>信息与发现渠道 |
| ---------------------- | ----------------------------------------------- | ------------------------------------------------ |
| Mature academic field<br>成熟的学术领域 | Textbooks, university courses, review papers, professional institutions<br>教材、大学课程、综述论文、专业机构 | Library catalogs, academic indexes, university course pages, scholarly societies<br>图书馆目录、学术索引、大学课程页面、学术协会 |
| Fast-moving technology<br>快速发展的技术 | Recent papers, technical blogs, GitHub repositories, active researchers<br>近期论文、技术博客、GitHub 仓库、活跃研究者 | Preprint servers, conference proceedings, official repositories, research labs, expert accounts and newsletters<br>预印本平台、会议论文集、官方仓库、研究实验室、专家账号与简报 |

For every request, AnythingAtlas should create a topic-specific source and channel plan before discovery begins.

对于每一次请求，AnythingAtlas 都应在开始发现资源之前，先制定一份针对该课题的来源与渠道方案。

The plan should specify:

该方案应明确：

* which kinds of evidence and learning materials are required;

  需要哪些类型的证据与学习材料；

* which information channels should be searched first and why;

  应优先搜索哪些信息渠道，以及这样选择的原因；

* the appropriate balance between primary and secondary sources;

  一手来源与二手来源之间适当的比例；

* recency, language, geographic, budget, and access requirements;

  时效性、语言、地域、预算与访问要求；

* channels that should be excluded, deprioritized, or treated cautiously;

  应排除、降低优先级或谨慎对待的渠道；

* how the channel plan differs from the default policy for other topic types.

  该渠道方案与其他主题类型的默认策略有何不同。

This policy determines:

该策略决定：

* which sources should be searched first;

  应优先搜索哪些来源；

* how authority should be measured;

  应如何衡量权威性；

* how strongly recency should be weighted;

  应赋予时效性多大的权重；

* whether primary sources are required;

  是否必须使用一手来源；

* how disagreements between sources should be presented;

  应如何呈现来源之间的分歧；

* what kinds of resources should not be treated as authoritative.

  哪些类型的资源不应被视为权威来源。

## Proactive Requirement Clarification

**主动澄清需求**

The user’s first message should be treated as an initial brief rather than a complete specification.

用户的第一条消息应被视为初步需求，而不是完整规格。

AnythingAtlas should inspect what is already known, identify only the gaps that materially affect the result, and ask a compact set of high-value questions. It should not begin the final research and production phase until the brief is sufficiently clear.

AnythingAtlas 应先检查已知信息，只识别那些会实质性影响结果的缺口，并提出一组精简且高价值的问题。在需求简报足够清晰之前，不应进入最终研究与制作阶段。

Clarification should cover, when relevant:

在相关情况下，澄清内容应包括：

* the exact topic scope and boundaries;

  课题的准确范围与边界；

* the desired outcome, such as orientation, systematic study, project work, research, or professional application;

  期望成果，例如建立初步认识、系统学习、完成项目、开展研究或进行专业应用；

* the user’s current knowledge and prerequisites;

  用户当前的知识水平与前置基础；

* available time, target date, and preferred learning intensity;

  可用时间、目标日期与偏好的学习强度；

* preferred languages, formats, and modes of practice;

  偏好的语言、内容形式与实践方式；

* desired depth, budget, geographic relevance, and access constraints;

  期望深度、预算、地域相关性与访问限制；

* any sources, viewpoints, or channels the user wants included or avoided.

  用户希望纳入或避开的来源、观点或渠道。

Questions should be grouped and prioritized instead of asked one at a time. AnythingAtlas should avoid asking for details that can be safely inferred, explain any consequential assumptions, and confirm its interpretation of the brief before proceeding when ambiguity remains.

问题应分组并按优先级提出，而不是一次只问一个。AnythingAtlas 应避免询问可以安全推断的细节，说明所有可能产生重要影响的假设，并在仍有歧义时先确认自己对需求的理解，再继续执行。

If the user explicitly asks AnythingAtlas to decide on their behalf, it may proceed with reasonable defaults, but those defaults must be recorded in the final deliverables.

如果用户明确要求 AnythingAtlas 代为决定，它可以采用合理的默认值继续执行，但必须在最终交付文件中记录这些默认值。

## Workflow

**工作流程**

AnythingAtlas follows a structured research and curation workflow.

AnythingAtlas 遵循一套结构化的研究与策展流程。

### 1. Clarify and Confirm the User’s Needs

**1. 澄清并确认用户需求**

Review the information already provided, identify high-impact gaps, and ask focused follow-up questions. Capture:

检查用户已经提供的信息，识别影响较大的缺口，并提出聚焦的后续问题。记录：

* topic;

  主题；

* learning or research goal;

  学习或研究目标；

* current knowledge;

  当前知识水平；

* available time;

  可用时间；

* preferred language;

  偏好语言；

* preferred formats;

  偏好的内容形式；

* desired depth;

  期望的深度；

* budget or access constraints.

  预算或访问限制。

Summarize the interpreted brief, state consequential assumptions, and request confirmation when unresolved ambiguity could change the result.

总结对需求的理解，说明可能产生重要影响的假设；如果尚未解决的歧义可能改变结果，则请求用户确认。

### 2. Classify the Topic

**2. 对主题进行分类**

Determine whether the request concerns:

判断请求涉及的是：

* an academic discipline;

  一个学科；

* a technical field;

  一个技术领域；

* a practical skill;

  一项实践技能；

* a historical event;

  一个历史事件；

* a person;

  一个人物；

* an organization;

  一个组织；

* an industry;

  一个行业；

* a social issue;

  一个社会议题；

* a current event;

  一个时事事件；

* another type of knowledge domain.

  其他类型的知识领域。

Also assess the topic’s maturity, rate of change, evidentiary requirements, degree of controversy, geographic scope, and balance between theory and practice.

同时评估该主题的成熟度、变化速度、证据要求、争议程度、地域范围，以及理论与实践之间的侧重。

### 3. Build the Knowledge Map

**3. 构建知识图谱**

Break the topic into:

将主题拆解为：

* foundational concepts;

  基础概念；

* major branches;

  主要分支；

* prerequisite knowledge;

  前置知识；

* representative questions;

  代表性问题；

* important people and institutions;

  重要人物与机构；

* common misconceptions;

  常见误解；

* possible directions for deeper exploration.

  可供深入探索的方向。

### 4. Design the Source and Channel Plan

**4. 设计来源与渠道方案**

Decide which materials, evidence types, information channels, search systems, and credibility criteria are appropriate for the topic. Record why each major channel is included, excluded, or deprioritized.

判断哪些资料、证据类型、信息渠道、搜索系统和可信度标准适合该主题。记录纳入、排除或降低每个主要渠道优先级的原因。

### 5. Discover Resources

**5. 发现资源**

Search across the media and channels selected in the source and channel plan:

按照来源与渠道方案，跨所选媒介和渠道进行搜索：

```text
Books
Courses
Papers
Blogs
Videos
Podcasts
Experts
Institutions
Archives
Documentaries
GitHub projects
Datasets
Communities
Primary sources
```

```text
书籍
课程
论文
博客
视频
播客
专家
机构
档案
纪录片
GitHub 项目
数据集
社区
一手资料
```

### 6. Verify Resources

**6. 验证资源**

Check whether each resource:

检查每项资源是否：

* actually exists;

  确实存在；

* is accessible;

  可以访问；

* has a clearly identifiable author or institution;

  有明确可识别的作者或机构；

* is relevant to the requested topic;

  与所请求的主题相关；

* is appropriate for the user’s level;

  适合用户当前的水平；

* is still current when recency matters;

  在时效性重要时仍然不过时；

* has meaningful authority or evidence behind it;

  具备实质性的权威背书或证据支持；

* contains obvious limitations, conflicts, or ideological biases.

  存在明显的局限、利益冲突或意识形态偏见。

### 7. Rank and Curate

**7. 排序与筛选**

Evaluate resources using criteria such as:

使用如下标准评估资源：

| Criterion<br>标准 | Description<br>说明 |
| ----------------- | ------------------- |
| Authority<br>权威性 | Expertise and reputation of the author or institution<br>作者或机构的专业能力与声誉 |
| Relevance<br>相关性 | Direct usefulness for the user’s stated goal<br>对用户所述目标的直接帮助程度 |
| Accessibility<br>可获取性 | Language, availability, cost, and technical difficulty<br>语言、可用性、成本与技术难度 |
| Timeliness<br>时效性 | Whether the material remains current<br>材料是否仍然符合当前情况 |
| Depth<br>深度 | How thoroughly the resource covers the topic<br>资源对主题的覆盖有多深入 |
| Practicality<br>实践性 | Availability of examples, exercises, projects, or evidence<br>是否提供示例、练习、项目或证据 |
| Format fit<br>形式适配 | Whether the medium and unit length fit the user's normal sessions<br>媒介形式与内容单元长度是否适合用户的日常节奏 |
| Reliability<br>可靠性 | Quality of sourcing, review, documentation, or primary evidence<br>来源标注、评审、文档或一手证据的质量 |
| Complementarity<br>互补性 | Whether the resource adds something not already covered<br>资源是否补充了尚未覆盖的内容 |

### 8. Build the Atlas

**8. 构建图谱**

Write the direct orientation first, then build the dated field guide, practical
action kit, knowledge map, and user-fit resource tracks. Every concrete
recommendation should identify its audience or condition, rationale, and
trade-off. Every field-guide entry should name representative examples.

先写直接结论，再构建带日期的领域实战地图、实操工具箱、知识图谱与适合
用户节奏的资源路线。每项具体建议都应说明适合人群或条件、推荐原因与取舍；
每个领域地图条目都应命名代表性例子。

Organize the selected resources by role:

按照用途整理所选资源：

  **引导式学习**——课程与结构化教学；

* **Deep dive** — advanced or specialized material;

  **深入探索**——进阶或专门材料；

* **Practice** — projects, exercises, code, or fieldwork;

  **实践**——项目、练习、代码或实地工作；

* **Stay updated** — experts, blogs, newsletters, and communities.

  **持续跟进**——专家、博客、简报与社区。

## Design Principles

**设计原则**

### Clarify Before Research

**先澄清，再研究**

AnythingAtlas should confirm the problem it is solving before investing in discovery and curation.

AnythingAtlas 应在投入资源发现与筛选之前，先确认自己要解决的问题。

### Trust Before Volume

**可信优先于数量**

Five verified resources are more valuable than fifty unverified links.

五项经过验证的资源，比五十个未经验证的链接更有价值。

### Map Before Path

**先有图谱，再定路径**

The user should understand the structure of a topic before receiving a detailed schedule.

在收到详细计划之前，用户应先理解主题的结构。

### Plan Channels Before Discovery

**先规划渠道，再发现资源**

The topic should determine which materials and information channels are searched, not the other way around.

应由课题决定搜索哪些资料与信息渠道，而不是反过来由搜索结果定义课题。

### Explain Every Recommendation

**解释每一项推荐**

A resource without a recommendation reason is only a search result.

没有推荐理由的资源，只是一条搜索结果。

### Separate Evidence From Commentary

**区分证据与评论**

Primary evidence, academic interpretation, educational summaries, and personal opinion should not be treated as equivalent.

一手证据、学术阐释、教育性总结和个人观点不应被等同看待。

### Adapt to the Topic

**适应主题**

There is no universal source-ranking policy that works equally well for history, finance, AI, medicine, and practical skills.

不存在一套通用的来源排序策略，能够同样适用于历史、金融、人工智能、医学和实践技能。

### Adapt to the User

**适应用户**

The best resource depends on the learner’s goal, background, time, language, and preferred format.

最佳资源取决于学习者的目标、背景、时间、语言和偏好形式。

### Preserve Uncertainty

**保留不确定性**

When reliable sources disagree, AnythingAtlas should describe the disagreement instead of manufacturing certainty.

当可靠来源之间存在分歧时，AnythingAtlas 应描述这种分歧，而不是人为制造确定性。

### Prefer Actionable Outputs

**优先提供可行动的输出**

Every atlas should end with a concrete starting action.

每份图谱都应以一项具体的起步行动收尾。

### Make the Roadmap Executable

**让路线图可以直接执行**

A roadmap should specify work, time, milestones, and completion criteria rather than only ordering resource titles.

路线图不应只排列资源标题，还应明确任务、时间、里程碑与完成标准。

### One Content Model, Two Deliverables

**一份内容模型，两种交付形式**

Markdown and HTML should be generated from the same verified content so that presentation never changes the research result.

Markdown 与 HTML 应基于同一份经过验证的内容生成，确保呈现形式不会改变研究结果。

## Evaluation

**评估**

AnythingAtlas should be evaluated across topics with different source requirements.

应在来源要求不同的各类主题上评估 AnythingAtlas。

The first benchmark set should include:

第一组基准测试应包括：

| Topic<br>主题 | Category<br>类别 | Main challenge<br>主要挑战 |
| ------------- | ---------------- | -------------------------- |
| Finance<br>金融学 | Mature academic field<br>成熟的学术领域 | Building a coherent textbook and course structure<br>构建连贯的教材与课程体系 |
| Artificial Intelligence<br>人工智能 | Fast-moving technology<br>快速发展的技术 | Finding current experts, repositories, and research<br>寻找当前活跃的专家、仓库与研究 |
| Nanjing Massacre<br>南京大屠杀 | Historical event<br>历史事件 | Prioritizing archives, primary sources, and historical scholarship<br>优先选择档案、一手资料与历史学术研究 |

Each benchmark should include both underspecified and fully specified user requests so that proactive clarification can be evaluated separately from research quality.

每个基准测试都应同时包含信息不足与信息完整的用户请求，以便将主动澄清能力与研究质量分开评估。

Recommended evaluation dimensions:

建议的评估维度：

* clarification completeness and question relevance;

  需求澄清的完整度与问题相关性；

* unnecessary-question rate and number of clarification rounds;

  不必要提问的比例与需求澄清轮数；

* accuracy of the confirmed user brief and assumptions;

  已确认用户需求简报与假设的准确性；

* appropriateness and coverage of the topic-specific source and channel plan;

  课题专属来源与渠道方案的适当性与覆盖度；

* resource existence rate;

  资源存在率；

* broken-link rate;

  失效链接率；

* citation and metadata completeness;

  引用与元数据完整度；

* source authority;

  来源权威性；

* user-goal relevance;

  与用户目标的相关性；

* topic coverage;

  主题覆盖度；

* recommendation diversity;

  推荐多样性；

* duplication rate;

  重复率；

* outdated-resource rate;

  过时资源率；

* quality of recommendation explanations;

  推荐理由的质量；

* roadmap feasibility, detail, actionability, and fit with the user’s constraints;

  路线图的可行性、详细程度、可执行性，以及与用户限制条件的匹配度；

* successful generation and content parity of the Markdown and HTML files;

  Markdown 与 HTML 文件的成功生成率和内容一致性；

* HTML validity, accessibility, responsiveness, print quality, and visual clarity;

  HTML 的有效性、无障碍性、响应式表现、打印质量与视觉清晰度；

* agreement with domain-expert judgment.

  与领域专家判断的一致程度。

## Roadmap

**路线图**

### Phase 1 — Skill Prototype

**阶段 1——技能原型**

* Define the standard input, shared content model, and dual-output schema.

  定义标准输入、共享内容模型与双输出模式。

* Implement proactive requirement clarification and a confirmation gate before research.

  实现主动需求澄清，以及研究开始前的确认关卡。

* Implement topic classification.

  实现主题分类。

* Implement topic-aware source and information-channel planning.

  实现主题感知型来源与信息渠道规划。

* Generate structured knowledge maps.

  生成结构化知识图谱。

* Search and verify cross-media resources.

  搜索并验证跨媒介资源。

* Produce curated resource atlases.

  生成精选资源图谱。

* Generate detailed roadmaps with tasks, time estimates, milestones, deliverables, and completion criteria.

  生成包含任务、时间估算、里程碑、产出与完成标准的详细路线图。

* Render every atlas as both Markdown and polished, self-contained HTML.

  将每份图谱同时渲染为 Markdown 和精美、自包含的 HTML。

* Validate content parity, links, HTML structure, accessibility, responsiveness, and print output.

  验证内容一致性、链接、HTML 结构、无障碍性、响应式表现与打印输出。

* Test on finance, AI, and historical events.

  在金融学、人工智能和历史事件主题上进行测试。

**阶段 2——评估框架**

* Build benchmark topics.

  构建基准测试主题。

* Add underspecified prompts and measure clarification quality.

  添加信息不足的提示词，并衡量需求澄清质量。

* Add hallucination and broken-link checks.

  添加幻觉与失效链接检查。

* Measure authority, relevance, and diversity.

  衡量权威性、相关性与多样性。

* Measure source-channel fit, roadmap actionability, file parity, and HTML presentation quality.

  衡量来源渠道匹配度、路线图可执行性、文件一致性与 HTML 呈现质量。

* Compare AnythingAtlas with general-purpose AI prompts.

  将 AnythingAtlas 与通用 AI 提示词进行比较。

* Introduce expert or human review.

  引入专家或人工审核。

### Phase 3 — Personal Learning Agent

**阶段 3——个人学习智能体**

* Save user learning history.

  保存用户的学习历史。

* Track completed resources.

  跟踪已完成的资源。

* Collect feedback on recommendations.

  收集用户对推荐的反馈。

* Update paths based on progress.

  根据进度更新路径。

* Refresh time-sensitive topics.

  刷新时效性强的主题。

  推荐更深入的分支。

AnythingAtlas 目前处于**早期功能原型阶段**。

仓库目前已经包含核心 Skill 工作流程、主题感知型参考策略、共享 JSON 内容模型、确定性的 Markdown 与自包含 HTML 渲染器、五套精美 HTML 主题、统一打印样式，以及交付文件一致性验证器。

## Non-Goals

**非目标**

AnythingAtlas is not intended to:

AnythingAtlas 并不旨在：

* replace teachers, historians, researchers, or domain experts;

  取代教师、历史学家、研究者或领域专家；

* guarantee that one learning path is universally optimal;

  保证某一条学习路径对所有人都是最优的；

* generate large lists merely to appear comprehensive;

  仅仅为了显得全面而生成冗长清单；

* treat popularity as equivalent to authority;

  将受欢迎程度等同于权威性；

* hide disagreement or uncertainty between reliable sources;

  隐瞒可靠来源之间的分歧或不确定性；

* replace primary sources with AI-generated summaries;

  用 AI 生成的摘要取代一手来源；

* provide professional medical, legal, or financial advice.

  提供专业的医疗、法律或金融建议。
