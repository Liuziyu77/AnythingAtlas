# Clarification Policy

Use this policy before researching an underspecified request.

## Completion gate

Proceed when the request has enough information to choose sources and build a realistic roadmap:

| Dimension | Minimum useful answer |
| --- | --- |
| Scope | Topic and meaningful boundaries |
| Outcome | What the user wants to understand, do, build, or decide |
| Starting point | Current knowledge and prerequisite gaps |
| Time | Available hours, duration, or target date |
| Preferences | Language and preferred formats |
| Constraints | Budget, access, geography, or excluded material |

Do not require every field when it would not change the result.

## Question policy

1. Extract all facts already present.
2. Identify only gaps with material impact.
3. Ask one grouped batch, ordered by impact.
4. Offer concise defaults when that reduces user effort.
5. Confirm the interpreted brief only when ambiguity remains.
6. Record accepted defaults and assumptions in the atlas.

Prefer questions such as:

- “What should you be able to do with this knowledge?”
- “How much time can you spend, and by when?”
- “What do you already know?”
- “Do you prefer books, courses, papers, videos, projects, or a mixture?”
- “Which languages, budget, or access limitations should I respect?”

Avoid:

- one-question-at-a-time interrogation;
- asking the user to choose technical distinctions they cannot yet understand;
- repeating facts already supplied;
- asking about preferences that do not affect research;
- blocking when the user explicitly delegates reasonable defaults.

## Confirmation template

Summarize:

```text
Topic and scope:
Goal:
Starting point:
Time:
Language and formats:
Constraints:
Assumptions:
```

Ask for confirmation only if an assumption could change the source plan or roadmap.
